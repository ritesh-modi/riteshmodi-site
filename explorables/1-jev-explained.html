TYPESAFE AI · SYSTEM ONE MODEL · JEV 1.13.0

Jev, explained

It cannot write a sentence, hold a conversation or explain itself. It answers typed questions with typed values and honest probabilities — in about a tenth of a second, at a price that rounds to nothing.

SCROLL

ACT ONE

What Jev actually is

Start with the problem it was built for — a question your software needs answered that isn't written anywhere in your data.

01 · The gap

Some questions aren't in the database

Is this customer angry? Does this résumé show real system-design depth? Does this retrieved passage actually support the claim? Is this message a jailbreak attempt?

Every one is a judgment — the kind a knowledgeable person makes in a second, and that no amount of SQL will produce. For a decade the only tool that could answer them was a model that answers in English.

02 · The old shape

You ask for JSON and hope

The standard move is to ask a language model nicely for structured output and parse whatever comes back. Three failure modes at once: it can invent a field, it can break your schema, and it is confidently wrong at roughly the rate it is confidently right.

You also pay for every word of prose you are about to throw away. Output tokens typically bill at around five times the input rate.

03 · The new shape

Unstructured state in, typed decisions out

Jev takes state — the content to judge, a string or JSON object or array of text — and typed questions about it. It returns answers your code can branch on, sort by, and route with.

Because it only ever returns an option you supplied, it cannot invent one and cannot break your schema. That is a property of the architecture, not of a prompt. It can still pick the wrong option — which is why every answer carries a probability.

0% type errorstext only

04 · The whole vocabulary

Three primitives. That's the entire API.

Choice — "which of these?" One of up to 255 options; back comes the winner, a distribution summing to 1.0, and a confidence.

Score — "which level?" A position on 2 to 10 ordered levels, returned as the probability-weighted mean of the level numbers.

Noul — "is this true?" One probability from 0 to 1. No confidence field, because with two outcomes the single number already describes the whole distribution.

05 · Decomposition is free

Ask ten questions, pay for one round trip

Every question in a request is evaluated in parallel against the same state. The docs are blunt: adding questions "barely changes the response time."

So the advice is always to decompose. Don't ask "is this spam?" Ask whether it requests credentials, whether the sender identity mismatches, whether it promises an unexpected reward — then weight those signals in code you control.

06 · The name

System One, not System Two

Straight from Kahneman. System 2 is slow, deliberate reasoning — what a frontier model does when it writes out a chain of thought. System 1 is the snap judgment, and it is the only thing Jev was built for.

TypeSafe calls this a new class of model. Jev is the first: "a frontier-intelligence function call."

07 · The deliberate gaps

It does not replace your LLM

System One models "don't write replies, produce code, or explain reasoning." TypeSafe states plainly that Jev is not a drop-in replacement for the model behind Claude Code, Cursor, opencode or Copilot.

It is the decision layer you build inside the software those tools help you write. Act six is about how the two compose.

ACT TWO

Why it is fast, and why it is almost free

Two advantages, one cause. Both fall out of the decision to stop generating text.

08 · The token loop

An LLM writes its answer one token at a time

Autoregression means every token waits for the one before it. A longer answer is a slower answer, and the prose carrying your three fields is the expensive part of the bill.

Across its own workflow set, TypeSafe measured frontier models taking 3 to 329 seconds per workflow.

09 · The parallel sampler

Jev produces every output at once

There is no token loop to wait on. A parallel sampler generates all outputs simultaneously, in a single pass over one shared piece of state.

That is the whole latency story: 70 to 500 milliseconds, around 100 typical — fast enough to sit inside a real-time request path rather than behind a spinner.

~100 ms typical150 ms = faster than perception

10 · Side by side

Two orders of magnitude

TypeSafe's headline measurement on its own workflow set: 0.114 seconds against 8.566 seconds — a 193.6× speed-up, and 444.6× cheaper on the same run.

The company flags that this may represent "the higher end of real world gains." Treat it as the ceiling, not the average.

11 · The bill

Input costs cents. Output costs nothing.

Jev's input is $0.042 per million tokens — $42 per billion — and output tokens are free. TypeSafe puts that at 238× below Claude Fable 5.1 on input alone.

For contrast, the reasoning model in TypeSafe's own cascade cookbook, gpt-5.5, runs $5.00 in and $30.00 out. Same units.

12 · Batching, measured

Send the document once, not thirteen times

TypeSafe tested 13 regulatory questions — 8 Nouls, 2 Choices, 3 Scores — against the GDPR Wikipedia article, roughly 54,000 characters. Asked one at a time, that article crosses the wire thirteen times.

Batched into a single call: 12.2× cheaper ($0.00050 against $0.00609) and 10.0× faster (0.27 s against 2.71 s). And the answers were identical — across five repeats most came back with a standard deviation of exactly 0.0.

cookbook — parallel questions

13 · Why it's called Jev

Jevons' paradox, as a product strategy

The name nods to the economist William Stanley Jevons, who noticed that making a resource cheaper does not reduce how much of it we burn — it multiplies it.

That is the bet. At these prices you stop rationing intelligence to the important requests and start running it over every row, every passage, every message.

ACT THREE

The number you can actually trust

Speed and price are nice. Calibration is the one that lets you automate.

14 · A distribution, not an answer

Every answer arrives with its own doubt

A Choice doesn't just name a winner. It returns the full probability distribution across every option you gave it, summing to 1.0 — so you can see whether the model picked decisively or barely.

Watch the bars. The winner is the same in both cases; the situation is not.

15 · Confidence

Derived from the shape, not the winner

Pile the probability on one option and confidence approaches 1.0. Spread it evenly and it collapses toward zero. For three options it works out to about (3 × pmax − 1) ÷ 2.

Scroll, and the distribution concentrates — the readout follows it. The raw probabilities array is always in the response too, if you'd rather compute your own measure.

16 · Why it is honest

RLHF makes models confident. RLCD makes them calibrated.

Reinforcement learning from human feedback optimises for what a rater prefers — and raters prefer a confident answer. That is the structural reason frontier models are systematically overconfident.

Jev was trained with RLCD — Reinforcement Learning for Calibrated Decisions, where probabilities are optimised against outcomes instead. Synthetic data only. Calibration is the training objective, not a post-hoc patch.

17 · The receipt

Frontier models disagree with themselves

TypeSafe ran a 14-question insurance rubric 15 times each across several models. Claude and GPT disagreed with themselves on repeated calls — at temperature 0. One question, covered, wandered from 0.43 to 0.53 across samples, crossing the 0.5 line that decides the branch.

Jev's mean per-question probability standard deviation on the same rubric: 0.0102.

18 · Absorbing the wobble

Don't force a binary. Leave a band.

The fix isn't a steadier model — it's refusing to put a hard threshold where the noise lives. Below 0.30 means no, above 0.70 means yes, and the middle goes to a human. That "absorbs fluctuation around 0.5 without issuing opposite automatic actions."

On an 8-question moderation rubric the same trick hit 99.2% agreement at a 0.60 threshold while still deciding 74.2% of answers automatically — at 114 ms a call against 826 ms to 13 seconds for the LLM baselines.

cookbook — self-consistency: choices

19 · The second axis

The answer tells you what. Confidence tells you whether you may act.

The documented default has three bands: above 0.9 act automatically, between 0.5 and 0.9 confirm or flag, below 0.5 route to a human.

Thresholds scale with stakes, not with the model. TypeSafe's banking example clears a read-only balance check at 0.6 and holds a risky transfer to 0.85. Same system, same model, different gate.

ACT FOUR

Two hundred tickets, end to end

Enough theory. Here is a morning's support queue going through all of it — one circle per ticket, the same two hundred the whole way down.

20 · The workload

A morning's queue

200 tickets, piled up overnight. Each is a short piece of text: a complaint, a question, a demand for money back.

These tickets are a simulated workload — invented so you can watch them move. Every fact about Jev on this page is not.

21 · The judgments

Four decisions each

For every ticket: which queue, how urgent, is a refund being asked for, and is it simple enough to close automatically.

Eight hundred judgments. None needs an essay.

22 · The slow way

A language model takes them one at a time

Four judgments means prose you then parse, and a follow-up question means another round trip. Watch the counter crawl.

23 · One pass

Jev answers all four at once

Every question evaluated in parallel against the same state, in one request. ~100 ms, and a fifth question would have been close to free.

24 · Choice

The pile splits three ways

Billing · · technical · · account ·. One option from the set you defined, every time — nothing to parse, nothing invented.

25 · Score

Urgency resizes every ticket

The value is the probability-weighted mean of the level numbers, so a ticket caught between medium and high reads as 1.43 rather than being forced into one box.

Describe situations, not degrees — the model never sees a level's number or its neighbours.

26 · Noul

The refunds light up

· tickets clear the threshold for "a refund is being requested." One question, one probability, one ring.

27 · Confidence

Now spread them by how sure the model is

Scroll, and the threshold sweeps from paranoid to permissive. The count of tickets clearing it moves with you — that count is the whole economics of the system.

28 · The gate

Three bands, three destinations

Above 0.90 act automatically. Between 0.50 and 0.90, confirm or escalate. Below 0.50, a person looks at it.

29 · The handoff

The expensive model only wakes for the hard ones

· close in plain code for no model spend at all. · go to a language model. · go to a person.

That middle number is the bill. Jev costs $0.042 per million input tokens with free output; gpt-5.5 costs $5.00 in and $30.00 out. The gate decides how often you pay the second one.

30 · The shape of it

Code owned the control flow the whole time

Nothing there was an agent choosing its own next step and compounding a failure rate every loop. It was ordinary software calling out for the judgments software can't make.

TypeSafe's position in one line: "Build a normal software workflow and insert System One only where AI is needed."

ACT FIVE

The question is the program

There is no fine-tuning. You customise Jev entirely through state, instructions and criteria — so how you phrase a question is the engineering.

31 · Decompose

Never ask the big question

"Is this email spam?" bundles a dozen judgments into one and hides the weighting inside the model. Ask instead whether it requests credentials, whether the sender identity mismatches the display name, whether it promises an unexpected reward.

Then combine those signals with weights you can read. Because questions run in parallel, splitting one into five costs you nothing in latency and hands you five knobs.

32 · Structured criteria

Options can be objects, not just labels

Instructions, Choice options, Score levels and Noul criteria all accept JSON structure — string, object, array or null. When two options could be confused, describe each with what, not_for and examples fields.

A Noul whose boundary is subtle gets explicit true/false definitions. A Score level that keeps catching cases from its neighbour gets a summary plus a list of signals. The structure removes the ambiguity you were hoping the model would resolve.

33 · The escape hatch

Always leave a way out

A Choice must return one of your options — so if none of them fit, it returns the least-bad one anyway. Add "other" or "none of the above" whenever the list might not cover every input.

Confidence will usually tell you this has happened: the distribution flattens. But a catch-all turns a silent wrong answer into an explicit one.

34 · Describing levels

Situations, not degrees

The model never sees a level's number, and never sees its neighbours — each description is judged entirely on its own. So "somewhat severe" tells it nothing, while "the user cannot log in but a workaround exists" tells it everything.

Use as many levels as you can describe distinctly, between 3 and 10. And test against real data: high confidence means the model found your description clear, not that your description was right.

35 · Going deep

255 options, and what to do past that

One Choice holds up to 255 options — enough for most taxonomies, not for a patent classification with 13,000+ nodes. The move is to walk the tree: one Choice per level, showing the subtree under each branch so the model can see what lives down there before committing.

The same two-pass trick scales other things. Semantic search over a document ranks up to 255 lines directly; beyond that, one Choice picks a window and a second ranks inside it.

docs — advanced structure · cookbooks — hierarchical classification, line-by-line search

36 · Beam search

One early mistake cannot be recovered — unless you keep options open

Greedy walking takes the highest-probability branch at every node, and a wrong turn at depth one is fatal. Beam search keeps K plausible paths alive and classifies every frontier in parallel — which, given Jev's pricing, costs almost nothing.

Paths are scored by geometric-mean probability, so a shallow leaf and a deep one compare fairly. On TypeSafe's four taxonomies — patents, retail, biomedical, source code — greedy got 2 of 4. Beam search with K=3 got 4 of 4, recovering a patent the greedy walk had already lost.

cookbook — hierarchical classification

37 · Why this shape pays

A tree you can debug

Decomposing a classification into per-level decisions buys two things a single opaque call never gives you: observability — you can see exactly which node sent a document down the wrong branch — and testability — you can unit-test a taxonomy change without re-running the whole corpus.

This is the recurring theme. Jev is not trying to be the system. It is trying to be a primitive the system is built from.

ACT SIX

It doesn't replace your LLM. It surrounds it.

Nine documented ways the two compose. Watch the Jev box hold its place while everything rearranges around it.

PATTERN 01 · THE FRONT DOOR

Classify first, spend second

Put Jev in front of everything. A confident, simple intent goes to a database lookup — no model at all. A confident, specialised one goes to a domain LLM. Anything uncertain or complex goes to a person.

The expensive resources only wake when they're needed, and the thing deciding costs a fraction of a cent.

docs — patterns/intent-routing

PATTERN 02 · GUARDRAILS

Screen both sides of the conversation

Screen the user's message before it reaches the model and the reply before it reaches the user — with something fast enough that nobody notices. One request: four yes/no hazard checks (jailbreak, harmful or illegal assistance, medical advice, self-harm) plus a severity score.

Two thresholds per hazard: an action threshold that fires the response, and a lower review threshold that sends it to a human. A dosage question goes to review, not refusal; a self-harm signal routes to support, not a block. Strict and permissive policies reuse the same scores — retuning costs no API calls.

cookbook — guardrails for LLMs

PATTERN 03 · THE CASCADE

Cheap model extracts, Jev verifies, big model only on failure

A cheap model does the work. Jev checks it field by field with narrow, falsifiable yes/no questions — not "is this good?" but "is this specific field wrong?", framed so an error is the true case. Only flagged cases reach the expensive model.

gpt-5.4-mini at $0.75/$4.50, gpt-5.5 at $5.00/$30.00 — seven times dearer — jev-1.12 verifying at $0.042/$0.00, escalating above about 0.7. Across 100 prompts the cascade's pareto frontier sat up-and-left of every single model run alone.

cookbook — SDE cascade

PATTERN 04 · THE AUDITOR

Check the LLM's citations against the source

Two stages, and the first needs no model: search the source for the exact quote. Missing entirely? Fabricated — caught for free. For quotes that are present, Jev judges the surrounding context: does it support the claim, contradict it, or say nothing? Above 0.8 confidence it auto-accepts.

Why the second stage earns its place: in the RFC 7519 test one citation had a verbatim, genuinely present quote whose section contradicted the claim. String matching alone would have passed it.

cookbook — double-checking citations

PATTERN 05 · THE RERANKER

Fix what retrieval got in the shortlist but in the wrong order

Keyword search is fast across millions of documents and routinely puts the right answer at rank nine. Jev rescores the shortlist with a single Noul per candidate rather than inventing a ranking scale — which keeps scores comparable across queries.

On the CLERC legal set — BM25 narrowing 3,565 court-opinion passages to 30-candidate shortlists over 40 queries — top-1 accuracy went 5% → 18% and top-10 38% → 62%. The 1,200 calls cost about $0.06.

cookbook — re-ranking

PATTERN 06 · THE FILTER

Decide what the LLM is allowed to read

Similarity ranking cannot tell relevant evidence from noisy, contradictory or malicious content. So between retrieval and generation, ask four questions of each of the top 12 passages: is it relevant, does it carry usable evidence, does it contradict the query's premise, is it attempting prompt injection?

In TypeSafe's test a seeded forum post ranked first by similarity (0.584) and scored 0.99 on injection — excluded. Across six queries at least two-thirds of every retrieval set was dropped.

cookbook — classifying RAG passages

PATTERN 07 · THE SHORTLIST

Tell the agent which tool to look at first

An agent with 182 skills loads them all into its system message, where the descriptions get truncated to 60 characters and a skill that edits PowerPoint looks identical to one that authors it. Cost, context rot, and bad picks.

Two Jev requests fix it: a wide Choice ranks all 182 plus three Nouls asking whether a skill is needed at all (~0.2 s), then a second pass re-ranks the top 3 with full descriptions (~0.1 s). Over 488 requests: wrong loads 16.8% → 7.3%, needless loads 9.8% → 4.0%.

cookbook — skill suggestion

PATTERN 08 · THE DISPATCHER

Natural language into a typed function call

A sentence goes in; a function name and its arguments come out as evaluated enums, each with a confidence. Arguments are choices (one of a fixed list), sets (several) or flags (booleans) — so an argument that isn't in your enum simply cannot be produced.

"Plot rolling correlation between nvda and spy for the past month" becomes rolling_correlation(symbol='NVDA', benchmark='SPY', window='1mo'). Role-descriptive questions keep the two tickers apart — one is "being measured", the other is "the yardstick".

The call's confidence is reported as the least certain argument, not the product: one wrong parameter defeats the whole call.

cookbook — function calling

PATTERN 09 · THE HAND-BACK

Let the LLM do the one thing Jev can't, then come back

When Jev detects a compound request — "turn off the lights and set the thermostat to 20" — an LLM splits it into atomic commands, and each re-enters Jev for typed routing. When it turns out to be general conversation, it goes to a generative model instead.

The justification for the extra hop: Jev is "so fast compared to the LLM response that it adds negligible latency." You aren't choosing between the two models — you're paying ~100 ms to learn which one you needed.

38 · The thread

Same move, nine times

None of these ask Jev to be smarter than a frontier model. They ask it to be cheap enough to run everywhere and calibrated enough to trust with a threshold.

Put a fast, typed, honest judgment in front of a slow, expensive, confident one — and let ordinary code decide what happens next.

42 · Measured · classification & search

Confidence as a dial, not a filter

Classifying SEC annual reports into the SIC taxonomy — 444 industries, 75 major groups, 10 divisions — one Choice question answers at whatever specificity it has earned. At or above 0.9 it names the group; below, it names the broader division instead. No extra API call.

Result across 60 filings: high-confidence answers were 90% accurate at group level; low-confidence ones were only 40% accurate as groups but 70% accurate once widened to divisions. Useful answers went from 39 of 60 to 48 of 60.

43 · Measured · extraction & data

Let the model read; let code compute

Dates. Jev is bad at date arithmetic — so it never does any. Seven Choice questions name the parts (absolute or relative, month, day, year, weekday anchor); code assembles the calendar date and routes anything below 0.60 to review. 83% accepted automatically, and the one failure was a date the document never actually stated.

Structure recovery. Rebuilding Markdown from flattened text: 28 lines into 17 blocks, two requests, 10,211 tokens, 0.8 s, $0.0015 — and every character of output came from the input, because the model only ever classifies, never rewrites.

44 · Measured · ranking & features

Two results worth sitting with

Entity alignment. 450 beer-catalogue pairs scored on three levels — different / related-but-uncertain / same product — with three supporting Nouls on name, brewery and style. Outcome: 8.9% merged, 11.1% queued for a curator, 80% left alone. No threshold tuning: the levels are the policy.

45 · Getting at it

Four doors in

The Playground at console.typesafe.ai — paste state, add questions, watch the distributions land, no code.

ACT EIGHT

Where it falls over

TypeSafe publishes a per-version page of known failure modes and calls it jaggedness. It is the most useful page they have.

46 · Numbers

It is not a calculator, and it cannot count

Numeric work is a documented weakness and the guidance is unusually direct: "Jev is not a calculator. We strongly recommend implementing any mathematical logic in code."

Counting items, characters or occurrences is equally unreliable, and the error grows with scale.

47 · Time and intent

Dates drift, and it reads you literally

Temporal comparisons, intervals and ordering all degrade — especially across mixed formats or domain boundaries like fiscal quarters. This is exactly why the date cookbook has Jev name the parts and lets code do the calendar.

And Jev answers the question as written, not as meant. State the exact condition; never lean on implied meaning.

48 · Reasoning and noise

Indirection hurts. Irrelevant context poisons.

Multi-step reasoning and double negatives underperform — if a judgment needs a chain, it isn't a Jev question.

And unrelated material in the state measurably reduces accuracy. Send the fields that matter, not the whole record. This is the failure the filter pattern defends against — in both directions.

49 · The subtle one

No invariants across questions

Ask "is X true?" and "is X false?" as two separate questions and the probabilities need not sum to 1.0. Each question is judged independently, so don't build logic that assumes otherwise.

And it does not write. Never trained for generation, poor when forced into it.

50 · The rest of the fine print

Limits that aren't failures, just facts

Text only — string, JSON object or array of text. No image, audio or video. English first — other languages are accepted but less accurate. No fine-tuning — the model is not customised per customer; the request is the customisation.

64K context per request, with state plus the longest question fitting inside 32K. 100K tokens/sec or 40 requests/sec, adjusting dynamically under demand.

51 · The payoff

The weaknesses draw the line for you

Read that list again and a rule appears. Code gets arithmetic, counting, dates, sorting, thresholds and control flow — things software has been excellent at for fifty years.

Jev gets classification, detection, scoring, verification, filtering, extraction. An LLM gets writing, planning and explanation. A human gets everything below your confidence floor.

ACT NINE

All of it, in code

One endpoint, three question types, and a response you never parse. Scroll — the panel follows.

52 · Setup

One import, one client

The three primitives are the only types you need. The client reads TYPESAFE_API_KEY from the environment and defaults to the latest model — today that resolves to jev-1.13.0.

53 · State

The content to be judged

A string, a JSON object, or an array of text values. Keep facts in the state and judgments in the questions — that separation is what lets you fire a dozen unrelated questions at one ticket in a single round trip.

54 · The questions

Three primitives, one request

A Noul for the yes/no, a Choice whose criteria map option names to descriptions, a Score whose criteria are ordered levels. All three evaluated in parallel against that same string.

The keys — billing, tone, urgency — are yours, and come back as the keys of the answer map.

55 · Reading the answers

No parsing, anywhere

.noul is a probability. .choice is one of the options you supplied. .score is a position on your levels. No regex, no JSON repair step, no retry-on-malformed loop.

56 · On the wire

One route, every model

A single POST with a bearer token. The model field picks the version, and the aliases jev-latest and jev-preview both currently point at 1.13.0.

57 · What comes back

Answers, and the bill

One Answer per question, plus usage. In TypeSafe's own example: 296 input tokens, 20 output. At $0.042 per million input and nothing for output, that request cost about $0.000012.

58 · When it fails

Four boring errors

401 bad key, 422 validation failed, 429 rate limited, 529 overloaded. For rate limits the guidance is exponential backoff — and both SDKs do it for you.

59 · The gate, in six lines

This is the whole point of the model

A hard floor at 0.60 catches what the model is genuinely unsure about. Anything irreversible waits for 0.85. Everything else just runs.

No second model call decides this. A typed value and an honest number come back, and ordinary control flow does the rest.

60 · Combining answers

Weights you can read and change

Split a complex judgment into independent Score questions, normalise each by its top level number, then weight them in code. The docs' résumé screener runs 40% Python depth for a senior IC — and 15% for an engineering manager.

61 · Static safety

Typed all the way into your editor

Pass a response_model and the SDK returns a validated object rather than a dictionary. The model already couldn't break the schema; now your own code can't either.

62 · Precision

Point a question at one field

When state is a nested object, a backtick path reference aims a single question at a single value. This is how TypeSafe fights what its docs call context rot — and the jaggedness page confirms the stakes: unrelated information in the state measurably reduces accuracy.

63 · Let the agent write it

The TypeSafe skill

A drop-in for Claude Code and other coding agents, carrying the API, the patterns and the cookbooks. Its own advice: agents are good at spotting where fragile parsing should become a judgment, and not good at writing the questions — so write those together, and keep every question and threshold in one file.

64 · The other runtime

JavaScript, with the types inferred

Node 20+, shipping ESM, CommonJS and TypeScript declarations. Define questions with helpers like choice() and the SDK infers the answer type from the definition — so a typo in an option name is a compile error.

65 · Where it plugs in

Three env vars and a base URL

The base-URL override is the interesting one: the same client speaks to OpenRouter, the Vercel AI Gateway and the Pydantic AI Gateway, so Jev drops into a stack that already routes models rather than demanding its own path.
